# 龙心 · 图像小说书房

当前章节默认以 HTML 图像小说打开，保留“时间轴 → 分卷 → 章节”的书架。内置作者提供的《白色的项链 · 六幕节选》，在元年和一千的同一分卷中展示，所有访客均可阅读。

## 上传和阅读

1. 点击“发布章节”，选择“HTML 图像小说”，导入内嵌图片、样式与脚本的完整 `.html` 文件（每章最多 25 MB）。外部脚本、字体及相对路径图片不随文件上传，请先制作自包含版本。
2. 填写标题、本章时间轴、分卷及全卷序号，再保存草稿或放入本机目录。支持继续编辑和替换 HTML。
3. 点开章节进入其自带封面、场景、回看和设置。外层按钮提供返回书架、分卷目录、上下章、全屏和独立 HTML 下载。上下章仅在同一分卷内按序切换，可以跨时间轴。
4. 旧 Word/TXT 文稿、富文本和原批注不变；默认改为逐段点击试读。插图需要作者制作 HTML 后替换，系统不会自动为旧文稿配图。“原文与批注”继续提供原来的选句、随记及背景阅读功能。

## 存储与备份

章节和 HTML 文件改存 IndexedDB，首次打开时迁移旧 localStorage 文稿，保留原副本和原章节 ID。大文件及未保存的 HTML 草稿均不写入小容量 localStorage。目录、批注和每章进度仍按原身份保存；HTML 内使用 getItem/setItem 的 localStorage 存档由隔离容器桥接为章节独立存档（最多 120 KB），不会与书站账号存储混用。

JSON 备份格式仍为 `longxin-backup-v1`，schemaVersion 升为 3，包含完整 HTML、检索文本、分卷、时间轴、批注和 HTML 存档；内置故事的资源也会先读取后嵌入备份。兼容旧版备份。背景原图仍需另外保留。HTML 独立下载包含原始故事与图片，不包含书站批注或当前浏览器存档。

**日常编辑仍保存在当前浏览器；作者可在“文稿”页手动保存私有云备份，尚未接入面向读者的云端发布。** 内置故事随 GitHub Pages 部署公开；作者登录仍是此前的 Supabase 第一阶段。浏览器清理数据会丢失本机导入内容，请保留原文件与 JSON 备份。网页书架需要网络；下载的自包含 HTML 可离线阅读。

## 阅读容器

HTML 在仅开启 `allow-scripts` 的 iframe 中运行，不授予同源、弹窗、顶层导航或表单权限。注入的 CSP 禁止外部脚本、连接及嵌套 frame，内嵌图片/媒体和行内脚本可运行。存档消息同时验证窗口来源和每次加载的随机令牌；故事没有书站存储或 Supabase 会话权限。仅支持自包含图文故事，不把任意联网应用当作章节运行。

## 源代码与部署

`source/` 为源代码，`source/public/novels/` 是按需加载的作者内置故事 JSON；请勿改为同源可直接执行的 HTML。根目录 `assets/` 和 `index.html` 为 Pages 构建结果。Node.js 22.13 或更新版本下运行 `npm ci`、`npm run typecheck`、`npm test`、`npm run build`，将 `build-output/` 内容同步至仓库根目录。GitHub Pages 使用 main 分支根目录。

自动检查包括六幕故事的点击/切幕/回看/赏图、存档恢复、iframe 权限及存档消息验证、IndexedDB 迁移和大文件保存、并发保存、共享分卷、旧文稿选句及作者登录。测试使用模拟 DOM 与 IndexedDB，不替代手机浏览器中的排版和隔离机制实测。

## 云端第一阶段：作者账号与权限

Supabase 项目：`ydauxndnzzmwqedpzuxz`。`source/public/cloud-config.json` 仅包含浏览器可用的项目 URL 和 publishable key；禁止放入 secret key、service_role 或数据库密码。

当前阶段仅接入连通检查、邮箱密码登录、会话恢复、退出和作者名单核验。文章、分卷、批注与背景仍使用浏览器本机存储，尚未迁移或公开共享；界面会明确显示这一状态。登录不会触发本机数据迁移，退出也不会清除本机文稿。

作者账号设置：

1. 在 Supabase 项目的 Authentication → Users 中创建自己的站点用户，自行设置密码并确认邮箱（后台创建时可使用自动确认）。Supabase 管理后台账号与本项目 Auth 用户相互独立。
2. 由项目管理员核对用户邮箱或 UUID，再将对应 `auth.users.id` 加入 `public.longxin_authors`。网页客户端没有修改作者名单的权限；不提供“首位注册者自动成为作者”的入口。
3. 打开书房上方“作者登录”，使用站点邮箱和密码登录，检查“作者权限已核验”。

`public.longxin_cloud_version()` 是无数据权限的连通探针。`longxin_authors` 启用 RLS，仅允许登录用户读取自己的名单记录。后续正文读写策略必须在数据库中检查作者名单，不能依赖页面按钮、缓存状态或 user_metadata。

迁移脚本保存在 `supabase/migrations/`，文件版本与已应用的远端迁移历史对齐。依赖版本固定，并保留 package-lock.json。运行 `npm ci`、`npm run typecheck`、`npm test`、`npm run build` 后，把 build-output 的内容同步到仓库根目录部署。自动测试使用模拟 DOM；真实作者登录待账号创建后验证。

## 作者私有云备份

作者登录并核验权限后，在“文稿”页点击“保存书房到云端”。每次保存新增一份不可覆盖的快照，包含已保存章节的完整 HTML、检索文本、时间轴与分卷、批注和故事内存档；不包含未保存的编辑草稿、背景原图、账号令牌及旧阅读器偏好。单次备份上限 45 MB / 1000 章，超限时继续使用本机 JSON 备份。

“查看最近 5 份云备份”只读取时间和章节数；选择恢复后才下载正文。恢复需确认，沿用 JSON 导入流程添加新副本，不覆盖或删除当前文章，重复恢复会生成重复章节。恢复中途遇到本机空间不足等错误时，已导入的章节会保留，并显示完成数量。云备份不是自动同步，也不会公开草稿。旧快照保留在云端，本轮不提供删除或自动清理功能。

数据库 `longxin_backups` 仅向已核验作者开放自己名下快照的 SELECT / INSERT；游客和其他账号不可读取，客户端没有 UPDATE / DELETE 权限。远端 RLS 已在回滚事务中验证作者读写、其他账号隔离和游客拒绝。`tests/cloud-backup.cjs` 覆盖客户端权限、格式、完整数据往返与失败提示；真实跨设备登录恢复仍需作者实测。
